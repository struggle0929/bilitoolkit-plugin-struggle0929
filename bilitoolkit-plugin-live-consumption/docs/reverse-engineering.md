## 重实现中的处理

- 正确保留明确的零支付金额，不将礼物面值当作付款金额。
- 同一流水的后续退款修正可替换旧记录。
- 取消、重复游标、页数上限及网络失败都显示部分结果及原因，不默默把缓存当作新获取的完整结果。
- 缓存按账号 UID 隔离；导出内容不包含 Cookie。请求依托宿主授权后注入的会话，仅向 B 站发送。
- 增量回看不能保证发现很久以前发生的退款修正，因此提供完整重查。

## 验证边界

已通过独立 MD5 对照、签名参数、翻页去重、部分结果、退款、包裹道具和 CSV 导出的自动化测试。未登录访问真实签名接口返回 `code=-101`、`账号未登录`，说明当前可访问该入口；不能以此证明登录后所有历史记录都可获取。

已在实际哔哩工具姬中完成本人账号授权、多页消费查询和本地缓存验证。真实流水号大于 JavaScript 安全整数范围，因此请求响应使用无损整数解析；游标和流水号保持为字符串。接口末页可能重复返回最后一条记录和游标，确认该页没有新增流水后按遍历结束处理；出现新流水但游标循环时仍标记为部分结果。

另发现宿主旧版 API 日志可能记录授权返回的凭据。主程序另行增加日志脱敏补丁；插件不将 Cookie 写入账单，但用户仍应避免分享未经脱敏的旧宿主日志。当前安装的主程序是否已修复，应以实际运行版本为准。

“完整”只表示当次已遍历接口返回的所有页。平台未返回、未保留或其他业务系统中的数据不在此范围内。本插件目前针对直播消费，不覆盖大会员、会员购、游戏、漫画及其他站内业务账单。

### 盲盒接口与降级

- `GET https://api.live.bilibili.com/xlive/general-interface/v1/blindFirstWin/getInfo?gift_id=ID` 返回 `blind_price`、`blind_gift_name`、`gifts`。原实现将 `blind_price`、结果礼物 `price` 除以 100，再四舍五入为电池；重实现保留小数，避免舍入误差。
- `GET https://api.live.bilibili.com/xlive/general-interface/v1/blind-box/drawStream?gift_id=ID&page_size=50`，后续附带 `data.params` 中除 `have_more` 外的标量分页字段。原文件优先读 `params.have_more`，否则读 `isMore`、`has_more`；源实现最多 100 页。
- 记录字段为 `gift_id`、`gift_name`、`gift_num`、`original_gift_id`、`original_gift_name`、`gift_img`、`timestamp`、`ruid`、`rname`。同一秒可有多个真实开盒结果，不能按时间或礼物名称简单去重。
- 登录后实测确认 `drawStream.timestamp` 返回日期字符串。原 `W` 函数按 `new Date(timestamp)` 处理，统计还有 `timestamp.split(' ')`；它不同于消费接口的秒级时间戳。插件将无时区日期按北京时间解析，同时兼容显式时区及秒/毫秒数值，避免依赖电脑所在时区。
- 原统计入口的元数据优先取远程活动配置，其次本地礼物配置，最终使用未知名称/零占位值；`getInfo` 成功不是请求 `drawStream` 的前置条件。历史盲盒配置下架时应仍能查询记录，但未知单价不能解释成免费或零价值。
- 原文件默认盲盒 ID 有 `32251`、`35206`、`35684`，可被活动配置覆盖。这些是静态候选，不保证它们在当前接口中仍可查询。
- 原程序还将按活动配置名称匹配的包裹奖励加入盲盒面值，并尝试按锁定主播名称或唯一开盒主播归属。这属于启发式关联；重实现需要单独标注来源不确定，避免重复计值。

### 合成及其他的具体依据

`092p9lci2k39t.js` 的 `fetchSynthesisStats`（恢复文件中的 `tP`）读取活动配置；默认活动为“玲珑宝斋”，材料包含锦囊、瓷瓶、银盒、云锦、玉函，产物包含相识玉扣、常伴珠钗、缘起瓷瓶、倾心宝冠、万象天衣。原实现对材料使用活动起止窗口，对产物允许结束后 176,400 秒的延长窗口。这些都是匹配规则，并非可证明全部产物来源的服务端历史。

原实现多处通过 `pay_coin || coin` 估值，会把明确零付款回退为礼物面值。插件的支付账单保留明确零付款；需要展示道具面值时另取配置或 `coin`，与净支出分开。

其他页的“近 30 天”数据与趣味评分是本地计算：按天累计支付，另统计未消费天数、超过 1,000 电池的天数，并对每天最多计 1,000 的值作评分。它不是平台账单字段或可核验的财务收益。无需为实现账单查询而复制原程序上传、发弹幕、抽奖或关注操作。

### 本人主播查询接口的独立边界

- 收礼：`POST /xlive/revenue/v1/giftStream/getReceivedGiftStream`，表单包含 `page`（从 0 开始）、`gift_id=0`、`begin_date`、`end_date`、`uname`、`goods_id`、`csrf_token`、`csrf`。身份来自本人登录，CSRF 值来自本人会话。响应 `data.ready=0` 且 `total_page=0` 在原实现中视为尚未就绪，并不能直接当成无记录。
- 最近场次：`GET /xlive/anchor-task-interface/api/v1/GetHistoryLiveStreamRecordListNew?source=1`，用 `end_time` 和 `next_start_time` 翻页，原回放页面仅保留最近 7 天；这不是消费历史一年限制。
- 场次礼物：`GET /xlive/anchor-center-interface/v1/anchorLiveData/GetLiveRecordInfos`，参数含 `live_key`、`start_time`、`end_time`、`type=1`、`index`、`log_date`、`page_size=50`，读 `gift_income_details`；`next_index=-1` 且 `log_date` 为空结束。
- 场次回放：`GET /xlive/anchor-center-interface/v1/anchorLiveData/GetLiveBaseInfo`（相同场次与时间，`source=1`），原程序选择礼物时间前 2 秒至后 12 秒的片段；观众资料来自 `/xlive/app-blink/v1/liveUserRank/UserScoreRank?live_id=...&rank_type=1`。

以上是静态协议与界面的确认，不是对任意账号查询权限、历史保留时长或视频可用性的承诺。每项运行成功应以插件实际返回和验证记录为准。

## 本轮实现与核查范围

源码 0.2.0 已实现消费页精确主播/礼物/月度筛选、金额/数量/记录数图表，独立盲盒记录，规则可编辑的合成分析，天选/红包分类，非退款账单日期统计，当前包裹，以及本人主播收礼、近期场次、本场礼物和分段元数据入口。自动化测试覆盖盲盒时间与游标、重复页/部分结果、主播数据未就绪、请求失效、CSRF 不入快照及回放地址脱敏。

在实际哔哩工具姬中，经用户手动授权后完成心动盲盒查询：返回 46 条记录、1 页、7 个礼物配置，遍历状态为完成，所有记录时间已转换为数值且没有丢弃同秒重复开盒。该结果只验证当前账号与该盲盒本次接口范围，不扩展为所有历史、所有盲盒或主播权限的运行承诺。28 项自动化测试、类型检查、ESLint 和插件构建通过；主播接口使用模拟响应验证分页与未就绪处理，尚未用拥有主播数据的账号验证真实返回。

主播收礼按用户选择的最多 31 天区间查询，没有复制原程序对大量月份的并行探测；本轮回放入口只展示去除签名播放地址后的元数据，不播放或下载视频。未重现趣味评分、称号、图片导出和与账单查询无关的自动化操作。合成与奖励依当前配置和已查账单匹配，不能据此宣称获得了服务端完整合成历史。
