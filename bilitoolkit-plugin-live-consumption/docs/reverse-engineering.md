## 重实现中的处理

- 正确保留明确的零支付金额，不将礼物面值当作付款金额。
- 同一流水的后续退款修正可替换旧记录。
- 取消、重复游标、页数上限及网络失败都显示部分结果及原因，不默默把缓存当作新获取的完整结果。
- 缓存按账号 UID 隔离；导出内容不包含 Cookie。请求依托宿主授权后注入的会话，仅向 B 站发送。
- 增量回看不能保证发现很久以前发生的退款修正，因此提供完整重查。

## 验证边界

已通过独立 MD5 对照、签名参数、翻页去重、部分结果、退款、包裹道具和 CSV 导出的自动化测试。未登录访问真实签名接口返回 `code=-101`、`账号未登录`，说明当前可访问该入口；不能以此证明登录后所有历史记录都可获取。

已在实际哔哩工具姬中完成本人账号授权、多页消费查询和本地缓存验证。真实流水号大于 JavaScript 安全整数范围，因此请求响应使用无损整数解析；游标和流水号保持为字符串。接口末页可能重复返回最后一条记录和游标，确认该页没有新增流水后按遍历结束处理；出现新流水但游标循环时仍标记为部分结果。

另发现宿主旧版 API 日志可能记录授权返回的凭据。主程序另行增加日志脱敏补丁；插件不将 Cookie 写入账单，但用户仍应避免分享未经脱敏的旧宿主日志。当前安装的主程序是否已修复，应以实际运行版本为准。

“完整”只表示当次已遍历接口返回的所有页。平台未返回、未保留或其他业务系统中的数据不在此范围内。本插件目前针对直播消费，不覆盖大会员、会员购、游戏、漫画及其他站内业务账单。
